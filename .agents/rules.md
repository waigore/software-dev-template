# Secondary rules

Rules every agent follows in addition to the five in [`AGENTS.md`](../AGENTS.md#rules-to-live-by). Read this file before starting any work.

- **Spec authoring**: before writing or editing a file under `specs/`, read its rules file from [`specs/rules/README.md`](specs/rules/README.md) (`author-spec` skill). Do not copy those rules into the spec. CI `Spec lint` checks the structural rules ([`docs/spec-lint.md`](../docs/spec-lint.md)). When applying a failed spec review, follow [`specs/alignment.md`](specs/alignment.md).
- **Quality rubrics**: characteristics in [`specs/definition/quality.md`](../specs/definition/quality.md) are the source of truth. Axes and evaluators live in [`specs/definition/quality/rubrics.md`](../specs/definition/quality/rubrics.md). Guide the owner with `author-quality-rubrics`. Deterministic axes are the verification obligation. Qualitative axes are judged at acceptance. `run-quality-evaluators` executes them: deterministic during verification, `llm-judge` during acceptance. Acceptance cites the deterministic record and does not run those checks again.
- **Spec depth**: `specs/definition/definition.md` sets `prototype`, `small`, or `full`, which scales story coverage and diagrams per [`specs/rules/depth.md`](specs/rules/depth.md). Screen and journey mockups are always required when the product has UI.
- **UX mockups and main-tree UI**: HTML mockups under `specs/ux/mockups/` bind main-tree UI (layout, palette, close functional tracking; not pixel-perfect). Catalog approval gates UI implementation. Contract: [`docs/ux-mockups.md`](../docs/ux-mockups.md).
- **Spec review**: review a spec with the `review-spec` skill, using the checklist linked from [`specs/README.md`](../specs/README.md) and [`specs/alignment.md`](specs/alignment.md). Whole-spec review also runs `audit-spec-applicability`, `audit-spec-terminology`, and `audit-spec-tbd`; any Fail fails the overall verdict.
- **Architecture decisions**: framework, library, storage, integration, and software-architecture choices are ADRs in [`specs/adr/`](../specs/adr/adr.md). The stack itself is chosen in [`specs/definition/definition.md`](../specs/definition/definition.md); its Stack ADR realizes that choice. Only Accepted ADRs authorize code. Do not read `specs/adr/archive/` unless explicitly asked.
- **QA acceptance**: AI-agent QA protocols prove product and UX stories per [`specs/qa/`](../specs/qa/qa.md); evidence under [`docs/qa/evidence/`](../docs/qa/evidence/). Required at acceptance only when deliverables change runtime behavior. Screenshots are required only when a protocol asks for UI evidence.
- **Technical design**: code and data shape (layers, modules, components, contracts, schemata, sequences) live in [`specs/technical/`](../specs/technical/technical.md), downstream of definition, product, UX, QA (tools and cited capabilities), and Accepted ADRs.
- **Coding conventions**: project-specific conventions (naming, formatting, layout, errors, tests) and lint/format/unit-test/coverage tooling live in [`docs/coding-conventions.md`](../docs/coding-conventions.md), owned by the project; template sync keeps its content. They are optional: a project may record `None — SOLID only` there. It extends [`docs/solid.md`](../docs/solid.md), owned by the template for every project, and never contradicts it. Precedence: SOLID, then conventions, then structure continuity. Every lint or format command it lists runs as a step in `Code lint` ([`code-lint.yml`](../.github/workflows/code-lint.yml)); unit-test and coverage commands run as `Unit tests` and `Coverage` ([`unit-tests.yml`](../.github/workflows/unit-tests.yml)). Wire those with `setup-unit-test-ci` (from `ensure-dev-env-setup`). Review a diff with `review-code`. Suggest structural refactors for the implementation tree or a named portion with `suggest-code-refactors`.
- **Concise docs/specs**: every file under `docs/` and `specs/` stays under **500 words**; split and link if longer. CI enforces it for Markdown (`Spec lint` `word-limit` check). Details: [`docs/README.md`](../docs/README.md), [`specs/README.md`](../specs/README.md).
- **Demo mode and PoCs**: Product **demo** is a config-bounded mode of the main product ([`docs/demo.md`](../docs/demo.md), [`specs/product/demo.md`](../specs/product/demo.md)); Offering may stay TBD if none. **Explore, then formalize**: try a slice under `pocs/<slug>/` before filling specs ([`docs/pocs.md`](../docs/pocs.md)). Ask before any PoC pull request. A PoC is not spec-bound and is exempt from SOLID and coding conventions. Main code never imports it. Formalize a keep list with `reconcile-poc` / `promote-poc` ([`docs/poc-promotion.md`](../docs/poc-promotion.md)); spec depth is the bar for that slice. Already-specced main-tree work does not need a new PoC.
